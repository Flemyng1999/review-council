# 303 Hardware & Infrastructure — AI Routing Hub

> **Audience**: AI agents only. So must use **English**. Humans use the manuals on NAS-303 directly.
>
> **When to read this file**: the AI is about to do any of —
> - run a notebook / script / training / inference / ENVI cube I/O / NNLS / long job on ubuntu-303
> - use SSH / tmux / port forwarding / VS Code Remote / Jupyter Lab against the server
> - read or write data on NAS-303 (SMB / WebDAV / backup target)
> - traverse the 303 router (GL-BE6500), Tailscale fallback, or CAU campus auth
> - diagnose any hardware-side fault (port blocked, router wedge, backup failure, UPS event, CAU watcher)
>
> **When to skip**: pure Mac-local edits, doc rewrites, git / KMS governance, or a lightweight script (< 30 s, no ENVI cube). Do not load this file for those.
>
> **What this file is**: a single-page **routing table** on the repo side. It does **not** carry SOP bodies — it routes project actions into the authoritative manuals on NAS-303. No duplication.

## 1. Where the manuals actually live

The authoritative source for 303 infrastructure operations is the `manuals` shared folder on NAS-303. It follows the Anthropic Skills + Diátaxis + Google SRE runbook layering (runbook = atomic SOP / system = architecture & rationale / reference = pure lookup).

> ⚠️ **Physical location vs. mount view**: the manuals **physically reside on NAS-303**. **`/Volumes/manuals/` is only the local view that this particular Mac sees after SMB-mounting the share** — it is not a real path. A router wedge, an SMB disconnect, or logging in from a different machine will make `/Volumes/manuals/` "disappear". On ubuntu-303, off-site, or on another Mac, the AI must pick the matching SMB / Tailscale entry instead. **Picking the right entry for the current host and network is itself a direct test of 303-hardware fluency.**

| Host / network | Access entry |
|---|---|
| This Mac (mount already up) | `/Volumes/manuals/` (Finder Cmd+K once) |
| Office LAN | `smb://192.168.8.100/manuals` |
| CAU campus / off-site wired | `smb://10.2.182.159/manuals` or `smb://nas-303/manuals` |
| CAU blocks SMB | SSH tunnel — see `runbooks/nas-mount-via-ssh-tunnel.md` |
| Tailscale fallback (any network) | `smb://100.92.220.41/manuals` |
| On ubuntu-303 (Linux) | `mount -t cifs //192.168.8.100/manuals ...`, or follow the routing pointers from the repo docs back to NAS |

If `/Volumes/manuals/` suddenly vanishes or goes read-only, **the first hypothesis is SMB mount state / router wedge — not file loss** (see `INDEX-symptom.md` → "网络 / 远程访问", last row).

## 5. Maintenance rules

- This repo does **not** host any 303 infrastructure SOP body. Edits to server / NAS / router / Tailscale / IPv6 / backup / UPS / CAU-watcher operations go directly into `/Volumes/manuals/` and must obey the iron rules in `/Volumes/manuals/AGENTS.md` (runbook ≤ 150 lines, bidirectional cross-links, no deprecated content in main directory, etc.).
- Update §1–§3 of this file only when the routing surface itself changes: a new runbook is added, a new subsystem category appears, an entry IP changes, or `manuals/` directory structure is restructured.
- `/Volumes/manuals/` is just one host's mount view. Other hosts reach the same NAS share via SMB / Tailscale.
- Before declaring a path or entry IP dead, verify on the NAS side first, then update this file.
